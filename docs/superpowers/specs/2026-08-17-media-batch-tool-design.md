# 媒体批处理工具（Media Batch Tool）设计文档

- 日期：2026-08-17
- 状态：设计已确认（全功能免费版）
- 技术路线：Tauri 2 + Vue 3 + TailwindCSS（方案 A）

## 1. 背景与目标

一款面向**普通消费者**的跨平台（macOS + Windows）桌面应用，用于批量处理图片和视频：智能瘦身、格式转换、社交媒体适配。

**产品定位**：完全免费、轻量（安装包 5-15MB）、启动快（<1s）、纯本地处理（文件不出本机，不收集任何数据）。"免费、轻量、隐私"是产品名片。

**成功标准**：
- 一个完全不懂技术的人能在 30 秒内完成"拖入文件 → 一键处理 → 拿到结果"
- 图片/视频批处理性能显著优于同类 Electron 工具，UI 不卡顿
- macOS + Windows 双平台稳定运行

## 2. 产品定义

### 2.1 三个核心模式

用户进入应用先选"我要干什么"，而不是面对参数：

| 模式 | 用户操作 | 背后做什么 |
|---|---|---|
| 🪄 智能瘦身 | 拖入照片/视频 → 点"一键瘦身" | 自动判断格式和内容，压缩到"肉眼无差别"的最小体积 |
| 🔄 格式转换 | 拖入文件 → 选目标格式 | HEIC→JPG、PNG→WebP、MOV→MP4 等常用转换 |
| 📱 社交适配 | 拖入文件 → 选平台模板 | 按微信/朋友圈/抖音/小红书/Instagram 预设：分辨率 + 格式 + 可选水印 |

### 2.2 场景模板机制（核心差异化）

用户**不面对参数，只面对场景**。例如"发抖音"模板 = 1080p 竖屏 + MP4(H.264) + 体积上限。模板内置，随应用版本更新（第一版不做云端下发）；用户可自定义模板。

### 2.3 功能清单（全功能免费）

- 智能瘦身：图片/视频无限量、无限制
- 格式转换：全部格式，含 4K、HEVC/AVIF 高级编码
- 社交适配：全部平台模板 + 自定义模板
- 自定义水印（文字/图片、位置、透明度）
- 后台批量队列（一次拖入上千文件挂着跑）

### 2.4 不做的事（YAGNI）

- ❌ 不做云同步/云存储（纯本地，隐私是卖点）
- ❌ 不做编辑器（只做批量转换，不是剪视频的）
- ❌ 第一版不做插件/脚本
- ❌ 不做账号系统、支付、授权门控（全功能免费）

## 3. 技术架构

### 3.1 总体结构（Cargo workspace + 前端）

```
media-batch-tool/
├── src-tauri/                  # Rust 后端
│   ├── src/
│   │   ├── main.rs             # 入口，初始化窗口
│   │   ├── commands/           # Tauri IPC 命令层（薄，只做参数校验和调度）
│   │   ├── processing/         # 核心处理引擎（图像/视频/队列）
│   │   ├── templates/          # 场景模板定义 + 校验
│   │   └── thumbnails/         # 缩略图生成（供前端预览）
│   ├── Cargo.toml
│   └── tauri.conf.json
├── src/                        # 前端（Vue 3 + TypeScript + Vite + TailwindCSS）
│   ├── views/                  # 路由级页面：模式选择 / 拖拽区 / 处理中 / 完成
│   ├── components/             # 文件卡片、进度条、模板选择器
│   ├── stores/                 # Pinia：文件列表、任务状态
│   ├── composables/            # useFileDrop、useTaskProgress 等
│   └── lib/                    # Tauri IPC 封装
└── ...
```

### 3.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面框架 | Tauri 2 | 跨平台 + 轻量 + 安全 |
| 前端框架 | Vue 3 + TypeScript + Vite | 组合式 API，开发效率高 |
| 样式方案 | TailwindCSS | 设计自由度最高，适合消费者级 UI |
| UI 组件库 | shadcn-vue（Tailwind + Radix Vue） | 与 Tailwind 原生融合，可任意定制，无障碍有保障 |
| 状态管理 | Pinia | Vue 官方推荐 |
| 图像处理 | `image` + `mozjpeg` / `libwebp` / `ravif` | 高质量压缩（WebP/AVIF） |
| 视频处理 | `ffmpeg`（sidecar）+ `ffprobe` | 视频唯一现实方案 |
| 并行批处理 | `tokio` + `rayon` | 异步 IO + CPU 并行 |
| 元数据读取 | `exif` / `ffprobe` | 缩略图、旋转、时长信息 |

### 3.3 IPC 边界设计

- **命令（command）**：前端调用 `analyze_files(paths)`、`start_batch(file_ids, template_id)`、`export_files(ids, target_dir)` 等
- **事件（event）**：`file_started` / `file_progress` / `file_completed` / `file_failed` / `batch_complete`，Rust 端推送，前端不轮询
- **缩略图**：Rust 生成小尺寸预览写入临时目录，前端用 `convertFileSrc` 加载，避免 WebView 直接渲染大图
- **大文件处理**：单文件处理在 `tokio::spawn_blocking` 线程池执行，UI 永不卡顿

### 3.4 跨平台注意事项

- WebView 差异：mac 用 WKWebView、Windows 用 WebView2（Win10+ 自带），CI 双平台跑 E2E 冒烟测试
- 路径处理：统一用 `tauri::path` API，不手拼字符串
- ffmpeg sidecar：按平台打包不同二进制（mac 分 arm64/x86_64，Windows 分 x64）

## 4. 核心处理管道与数据流

### 4.1 图片管道

```
读取 → 解码（懒加载，不整图驻内存）→ 分析（尺寸/格式/EXIF旋转）
    → 按模板目标处理（缩放/裁剪/质量）→ 编码（JPG/WebP/AVIF）
    → 写入临时文件 → 原子替换（校验体积收益后才替换）
```

压缩前先算"预估收益"，若压缩后反而更大则跳过该文件并提示（防止劣化）。

### 4.2 视频管道

```
ffprobe 读元数据（时长/编码/分辨率/旋转）→ 组装 ffmpeg 参数
    → 执行转码 → 解析 ffmpeg -progress 输出实时进度
    → 校验输出（时长/可播放性）→ 替换
```

### 4.3 队列调度

- 全局任务队列：`tokio` 管理，前端提交一批 → 入队 → 逐个分发
- 并发策略：
  - 图片：CPU 密集，`rayon` 并行，默认 `min(核数, 8)`
  - 视频：ffmpeg 进程吃资源，**固定并发 2**
- 缩略图优先：文件入队后先快速生成缩略图供 UI 展示，再做正式处理

### 4.4 进度与取消

- 双粒度进度：单文件进度（视频按转码百分比）+ 批次进度（已完成 n/m）
- 取消机制：每个任务挂 `CancellationToken`；图片在文件边界检查取消，视频直接 kill ffmpeg 进程并清理临时文件

### 4.5 数据流总览

```
用户拖入文件
   → analyze_files(paths) → Rust 读元数据 + 生成缩略图 → 返回文件列表
用户选模板
   → start_batch(file_ids, template_id) → 解析模板 → 建队列 → 并发处理
   → 事件流实时推回（进度逐文件更新）→ batch_complete → 完成页
用户点"导出到文件夹" → export_files(ids, target_dir)
```

### 4.6 错误处理策略（单文件失败不拖垮批次）

- 每个文件独立 try-catch：损坏文件/格式不支持 → 标记 `failed` + 中文原因，批次继续
- 输出质量校验：转码后抽查（时长一致、可解码），失败自动回滚临时文件
- 磁盘空间/权限不足 → 批次级告警，提示用户清理或换目录

## 5. 用户体验与界面设计

### 5.1 主流程（5 屏）

```
① 首页（模式选择）→ ② 拖拽区 → ③ 模板选择（仅社交模式）→ ④ 处理中 → ⑤ 完成页
```

### 5.2 各屏设计要点

**① 首页**：三大模式大卡片（图标 + 一句话 + 示例），不解释技术概念；底部"🔒 文件只在本机处理"隐私徽标。

**② 拖拽区**：拖入高亮动画；支持拖文件夹展开；文件卡片实时生成（缩略图 + 文件名 + 大小）；重复文件去重标记；不支持格式提示"🈲 暂不支持 .xxx"但不中断其他文件。

**③ 模板选择**：平台模板卡片展示输出规格，用户不用懂参数（"抖音 · 竖屏 1080×1920 · MP4"）。

**④ 处理中**：总进度条 + "正在处理 3/20 · 预计剩余 1 分 20 秒"；文件行独立状态；失败内联显示原因 + "重试"；全局"停止"。

**⑤ 完成页**：核心数字是节省空间（"共节省 2.3 GB"）；每文件"处理前 → 处理后"对比；"导出到…"和"继续处理"主按钮；可选手动选择保留/替换原文件。

### 5.3 视觉语言

- 圆角大卡片、柔和阴影、单一主色（活力蓝/青）、表情符号辅助图标
- 深浅主题跟随系统（Tailwind `dark:`）
- 中文优先（模板面向微信/抖音/小红书），文案抽 i18n 文件，后续加英文
- 空状态引导："试试这些示例"降低上手门槛

### 5.4 性能 UX 红线

- 首屏启动 < 1 秒
- 拖入 1000 个文件列表不卡（前端虚拟滚动，后端懒加载缩略图）
- 进度反馈延迟 < 300ms

## 6. 测试策略

| 层 | 内容 |
|---|---|
| Rust 单元测试 | 压缩函数（golden 测试：同输入同输出）、模板解析/校验、质量收益判断 |
| Rust 集成测试 | 真实文件端到端批处理（测试 fixture）、ffmpeg sidecar 调用、失败隔离（坏文件+好文件混批）、取消机制 |
| 前端测试 | Vitest 组件测试（模板卡片、文件卡片、进度条）；Playwright E2E：拖拽 → 选模板 → 处理 → 完成页 |

**CI**：GitHub Actions 双平台（macOS + Windows）编译、单测、E2E、打包。每周跑真实媒体 fixture 基准，监控压缩质量/体积收益不退化。

## 9. 风险与开放问题

- WebView 渲染超大图片/视频预览有限制 → 已用"缩略图优先"策略规避
- WKWebView / WebView2 渲染差异 → CI 双平台 E2E 覆盖
- ffmpeg 跨平台打包维护成本 → sidecar 按平台构建，版本锁定
- 开放问题（后置）：是否开源；是否上 Mac App Store
